# cf-auto 优选设置与使用教程

本文是 cf-auto 面板「优选设置」各选项与完整使用流程的详细说明。安装与快速上手请回到 [README](../README.md)。

## 面板导览

面板运行在 `http://路由器IP:7800`，共四个标签页：

| 标签页 | 作用 |
|---|---|
| 概览 | 显示程序版本、引擎版本、定时状态、Gist 状态；「开始优选」手动跑一轮；查看最近结果表；引擎升级入口 |
| 优选设置 | 优选方式、来源、区域、端口、参数、结果策略、定时更新等核心配置 |
| GitHub | 填写 Token / Gist ID / 目标文件名 / 代理，验证连接 |
| 日志 | 实时滚动日志，可开启自动刷新 |

## 优选方式

| | 按延迟 | 按带宽 |
|---|---|---|
| 测试内容 | TCP 握手延迟（开启 HTTP 模式测速时为 HTTP 请求延迟） | 先测延迟，再对达标 IP 逐个下载实测 |
| 排序 | 延迟升序 | 带宽降序 |
| 流量 | ≈ 0 | 约 100-300 MB/轮 |
| 适用 | 日常保鲜、高频定时 | 8K / IPTV 等大带宽需求 |

切换优选方式时，面板会自动隐藏不适用的参数：按延迟模式下「下载测速数量 -dn」「单 IP 测速时长 -dt」「下载测速地址」不参与测试，仅按带宽模式显示。

## 优选来源

**自定义优选源**：每行一个 URL，cf-auto 拉取全部来源后合并去重作为候选池，再从你的线路二次优选。社区常见的公开优选列表示例（可用性不保证，建议多填几个互为备份）：

```text
https://addressesapi.090227.xyz/CloudFlareYes
https://ip.164746.xyz/ipTop10.html
https://bestcf.pages.dev/cmliu/all.txt
```

**CF 官方网段**：实时从 `api.cloudflare.com` 拉取 Cloudflare 官方 IPv4 网段（与 CloudflareSpeedTest 默认行为一致），覆盖最全但单轮耗时更长（数十分钟）。适合低频深度扫描，或自定义源长期失效时的兜底。

## 区域定向

开启后按真实落地机房过滤：cf-auto 以 HTTPING 方式测速并读取响应中 Cloudflare 的 `cf-ray` 机房代码，只保留落地在选中地区的 IP（即 `-cfcolo` 参数）。

- 常用地区：`SIN` 新加坡、`NRT` 东京、`KIX` 大阪、`HKG` 香港、`LAX` 洛杉矶、`SJC` 圣何塞、`SEA` 西雅图、`FRA` 法兰克福；支持自定义 `CODE|名称`（如 `YYY|义大利`）
- 「每地区最少上榜数」（默认 3）保证小地区在 TopN 挤占下仍有席位
- **重要提示**：到家宽/机场线路的 Cloudflare 出口机房由运营商路由决定，且可能随时间变化。若某地区连续显示「本轮 0 达标（本线路可能不路由到 XX 机房），跳过」，说明当前线路不落地该地区，建议取消勾选该地区，或直接关闭区域定向
- 区域定向会增加 HTTPING 环节耗时；多地区 × 多端口会成倍拉长单轮时间

## 测速端口

默认 `443`。面板内置 `443 / 8443 / 2053 / 2083 / 2087 / 2096`（Cloudflare 支持的 HTTPS 端口）。

- 优选结果格式为 `IP:端口`，EdgeTunnel 订阅端需支持使用该端口连接
- 端口越多单轮耗时越长；没有特殊需求保持 443 即可

## CloudflareSpeedTest 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| 平均延迟上限 `-tl` | 300 ms | 高于此值的 IP 直接淘汰；调小结果更精、达标更少 |
| 平均延迟下限 `-tll` | 0 | 过滤"延迟过低疑似劫持"的 IP，一般保持 0 |
| 下载测速数量 `-dn` | 10 | 按带宽模式：延迟达标的前 N 个参与下载测速 |
| 单 IP 测速时长 `-dt` | 8 秒 | 按带宽模式：每个 IP 的下载时长，越大越准越耗时 |
| 下载测速地址 | speed.cloudflare.com | 自定义下载测速所用的 URL |
| HTTP 模式测速 | 关 | 用 HTTP 请求代替 TCP 连接测延迟。**若日志显示 TCP 模式 0 达标（部分路由器/线路 TCP 直连 CF 全部超时），请打开此开关** |
| 高级附加参数 | 空 | 原样追加给 cfst，如 `-t 200 -p 50` |

## 结果策略

**更新方式**（二选一）：

- **覆盖更新**（默认）：每轮把最新结果整理成独立 txt 直接覆盖整个文件，节点池完全跟随最新实测，逻辑最简单、结果最"新鲜"
- **融合更新**：新结果与旧榜合并——本轮新冠军按排名进前排；老上榜 IP 本轮仍达标则保留靠后且不清零账本；连续 N 轮落榜才移除。节点池平滑演进，适合担心单轮波动导致订阅抖动的场景

其余选项：

| 选项 | 默认 | 说明 |
|---|---|---|
| 本轮 TopN | 10 | 每轮进入结果榜的 IP 数量上限 |
| 结果行数上限 | 25 | 结果文件最大行数（融合模式旧榜保留也受此约束） |
| 连续落榜淘汰轮数 | 3 | 仅融合模式：连续 N 轮未达标才移除 |

融合模式的淘汰账本保存在路由器本地 `/etc/cf-auto/state.json`，与结果文件分离；结果文件注释头只含程序版本与更新时间。切换更新方式无需清账本，覆盖模式会自动清理陈旧账目。

## 节点信息模板

结果文件中 `IP:端口#注释` 的注释部分由模板生成，可用变量：

| 变量 | 含义 | 示例 |
|---|---|---|
| `{region}` | 地区代码（未开区域定向时为当轮实际落地机房） | `SIN` |
| `{latency}` | 延迟（自动取整，自带 ms） | `85ms` |
| `{speed}` | 带宽（自带 MB/s，延迟模式无此段） | `12.3MB/s` |
| `{date}` | 更新日期 | `2026-09-11` |

默认模板：`cf-auto | {region} | {latency}ms | {speed}`。空段自动省略。

## 定时更新

开启后按设定间隔（小时）自动执行完整一轮：按当前优选方式、来源、区域、端口配置测速并上传 Gist。服务开机自启，启动后会自动补跑错过的首轮。建议日常保鲜用延迟模式 + 自定义源 + 1~6 小时；官方网段全扫建议 12~24 小时。

## 完整使用教程

### 第一步：获取 GitHub Token（三步）

1. 登录 GitHub → 右上角头像 → **Settings**
2. 左栏底部 **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**
3. Expiration 选长期，**唯一勾选 `gist`** → Generate → 复制 `ghp_` 开头 Token

> Token 仅保存在路由器本地（权限 0600），只用于读写你自己的 Gist。

### 第二步：配置 GitHub 上传

进入「GitHub」标签页：

1. 粘贴 Token
2. Gist ID：打开任意一个你自己的（或新建的）Gist，URL 中 `gist.github.com/用户名/` 后面那段即是
3. 目标文件名：默认 `CF-Auto-Top.txt`，保持与订阅地址一致即可
4. GitHub 代理：路由器 GitHub API 直连不通时填（例如本机 OpenClash 混合端口 `http://127.0.0.1:7890`）
5. 点「验证连接」，通过后保存

### 第三步：跑第一轮

进入「优选设置」按上文选好方式/来源/端口并保存，再到「概览」点「开始优选」。日志中可观察：候选池拉取 → 逐地区测速 → 合并筛选 → Gist 上传。

### 第四步：接入 EdgeTunnel

把 Gist raw 地址填进 EdgeTunnel 后台的自定义优选源：

```text
https://gist.githubusercontent.com/<用户>/<GistID>/raw/CF-Auto-Top.txt
```

GitHub 对 raw 内容有约 1 小时缓存，订阅侧延迟生效属正常。

## 常见问题（FAQ）

**整轮 0 达标怎么排查？**
依次检查：优选来源是否拉取成功（看日志候选池行数）→ 若日志显示「模式：TCP」全部超时，打开「HTTP 模式测速」→ 若开了区域定向，看是否每个地区都提示"本线路可能不路由到"，是则关闭区域定向或改选其他地区 → `-tl` 是否设得过小。

**日志提示「本线路可能不路由到 XX 机房」？**
你的线路当前出口机房不是 XX。Cloudflare 出口由运营商路由决定且会变化，取消该地区勾选即可；该提示只是跳过警告，不影响其他地区。

**融合与覆盖怎么选？**
追求简单直接用默认的覆盖更新；希望订阅里的 IP 池缓慢变化、减少单轮波动影响，用融合更新。

**想换优选端口/新增端口？**
在「测速端口」处添加即可，下一轮生效。确认你的订阅端支持对应端口。

**升级/重装会丢配置吗？**
不会。`/etc/cf-auto/config.json`（配置）与 `state.json`（账本）在升级与重装时均保留。

**手动触发提示测速引擎正忙？**
上一轮尚未结束（或定时任务正在进行），等当前轮完成即可。
